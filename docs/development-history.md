좌측 하단에는 브라우저 카메라 영상과 초록색 손 추적선을 표시한다. 가운데 손가락은 fxxk you, 주먹·펀치는 punch, 양손 하트는 love, 엄지 올리기는 melt, 엄지 내리기는 rain, 손바닥 펼치기는 video를 그 위에 표시한다. 기존 폭발, 5회 누적 펀치 파괴, 하트의 파란 하늘·흰 후광·글리터, 녹아내림 효과를 유지한다. 한글 조합 확정용 Enter는 시작하지 않는다.

새 문장을 Enter로 입력하면 글자와 손동작 상태를 초기화하며 이미 열린 카메라는 계속 사용한다. 우측 하단 play/mute는 BGM만 제어하고 카메라·손 추적·효과음은 유지한다. 손바닥 영상이 표시되는 동안에는 BGM을 자동으로 끄고 이 버튼을 비활성화한다. 영상에서 나가면 이전 음소거 설정을 복원한다. 카메라는 텍스트 입력·음악 버튼·Escape와 관계없이 계속 사용한다. 글을 제출하기 전에는 손 포즈 이름만 표시하고 텍스트 효과나 효과음은 실행하지 않는다. 손바닥 영상은 예외로 인트로를 나온 뒤 빈 문장에서도 재생할 수 있다. 페이지 종료 시 카메라와 Worker 자원을 해제하고, 뒤로 가기로 페이지에 복귀하면 다시 시작한다.

MediaPipe Tasks Vision 1.1.0과 모델·WASM 파일을 이 사이트에서 직접 제공한다. 인식은 모듈 Worker에서 CPU로 수행하여 글자 효과의 화면 처리를 막지 않는다. 최신 Chrome/Edge 또는 Safari 17 이상 등 카메라·모듈 Worker·WebAssembly·createImageBitmap을 지원하는 브라우저가 필요하다. HTTPS 주소를 사용해야 한다. 첫 추적 실행에는 모델과 선택된 WASM 파일 약 21 MB를 받으므로 연결이 느리면 준비 시간이 길어질 수 있다.

개발 시 TouchDesigner 없이도 이 폴더를 localhost 정적 서버로 제공하면 사용할 수 있다. 기존 td/*.toe 파일은 이전 TouchDesigner 방식의 개발 자료로 보관하며 공유 버전 실행의 필수 요소가 아니다. public 배포에는 td, tests, docs, 원본 파일이나 진단 영상은 포함하지 않는다.

기존 제스처 규칙을 JavaScript로 이식했고 Python/JS 2,500 프레임 비교에서 결과가 같았다. 카메라 시작·종료·재입력·권한 실패·오래된 프레임·Worker 로더 회귀 검사와 기존 화면·음악 검사 63개 및 Python 8개를 통과했다. TouchDesigner를 종료한 맥의 Chrome에서 브라우저 640×480 영상과 수백 개의 새 추적 결과가 들어오는 것을 확인했다. 다른 실제 기기의 제스처 판정 정확도는 아직 측정하지 않았다.

아래는 이전 버전에서 누적한 효과와 준비 기록이다.

주먹을 0.3초 유지하면 일부 글자에 균열과 작은 파편이 생기고, 앞으로 내밀면 타격마다 손상이 누적되고 10번째 펀치에 완전히 파괴된다. HATE를 누르면 횟수와 글자를 초기화한다. 실제 동작별 반복 정확도, 양손 하트 실루엣 보정은 남아 있다. 주먹 균열과 펀치에 사용자가 제공한 MP3 효과음을 연결했다. 사용자가 제공한 Born Hater MP3를 BGM으로 연결했다. HATE에서 0.18 음량으로 반복 재생하고 하단 PLAY/MUTE 버튼에서 BGM만 켜고 끈다. MUTE에서도 카메라·손 추적·효과음은 계속 동작하며 PLAY는 음악의 진행 위치에서 다시 들리게 한다(공개 버전 17). 효과음은 음악보다 낮게 타격 0.07, 균열 0.03으로 조정했다(공개 버전 15). 가운데 손가락 폭발에는 사용자가 제공한 retro-explode MP3를 0.07 게인으로 연결했다(공개 버전 16). 녹아내림·하트 효과음은 아직 연결하지 않았다. [실행·검증 기록](td/README.md)을 참고한다.

가운데 손가락 폭발에는 레퍼런스의 불꽃 색을 사용한 전체 화면 픽셀 파편 모션을 추가했다. 배경이 어두워지고 파편이 퍼졌다가 중력에 따라 떨어져 4.6초 안에 사라진다. HATE는 배경과 모션을 초기화한다. 공개 버전 14에서 TD 시험 이벤트로 화면 재생, 종료, 초기화를 확인했다.

펀치할 때 둥근 관중과 따뜻한 색감의 초기 닌텐도 3D 게임풍 복싱장 배경을 표시한다(공개 버전 19). 사용자 복싱장 사진의 구도와 첨부한 게임 화면의 질감을 참고해 ImageGen 내장 도구로 생성했다. 원본 사진은 보존했다. 가운데 손가락은 기존 픽셀 폭발, HATE는 기본 배경으로 전환한다. [이미지와 최종 프롬프트 기록](assets/BOXING_GAME_GENERATION.md)을 참고한다.

기본 배경은 블랙이며 제목·입력 글자·버튼은 밝게 표시한다(공개 버전 23). 양손 하트가 인식되는 순간 기존 파란 구름 하늘과 더 밝은 흰 후광이 함께 나타난다. 입력한 텍스트가 1.65초 동안 흰색으로 발광한 뒤 터지면서 흰 글리터가 7초 동안 내려온다. 타원 고리와 방사형 선을 제거하고, 밝은 중심에서 가장자리로 투명하게 번지는 흰 빛을 글자 뒤에 표현했다. 실제 글자 모양을 반짝이는 흰 입자로 변환해 폭발시킨다. 텍스트 입자는 화면에 따라 최대 700/1,200개로 제한했다. 레퍼런스의 구름·입자감을 CSS와 Canvas 모션으로 표현했다. 기존 ♡ 임시 표시는 숨겼다. 한손 손가락 하트는 발동하지 않는다. HATE는 블랙 배경으로 돌아가며 하늘과 글리터를 초기화한다. 카메라와 BGM은 연출 중 계속 동작한다. 모션 감소 설정에서는 후광·발광 글자·글리터를 정적으로 표시한다.

Library 준비 브리프 4쪽 전체(167줄)는 직접 읽기로 확인했다. 로컬 DOCX 다운로드는 실패했다. 원본 ID는 libfile_4f1ce6e847188191b77ab963fb5c65f4다.

| 입력 | 화면 효과 | 구현 시 확인할 점 |
|---|---|---|
| 가운데 손가락 들기 | 입력 텍스트 폭발 | 제스처 유지 시간, 재발동 방지 |
| 주먹을 쥐고 실제 앞으로 펀치 | 타격 후 화면에서 튕기다가 깨짐 | 주먹 모양만으로 발동하지 않음. 전방 이동의 시간 변화와 크기 변화를 함께 평가 |

| 엄지 아래 | 텍스트 녹아내림 | 다른 제스처와의 오인식 확인 |

## 권장 설계 — 아직 확정 전

브라우저에서 텍스트 입력, 카메라 인식, 효과 렌더링을 처리하고 인식된 제스처 이벤트를 로컬 TouchDesigner에 전달한다. 사용자가 시작 버튼을 누른 뒤 카메라 권한과 오디오 재생을 시작하는 흐름으로 설계한다.

WebSocket은 제스처 이벤트를 전달하는 경로다. TouchDesigner가 만든 영상을 브라우저에 표시하려면 별도의 WebRTC 등 영상 전송 경로가 필요하다. 이벤트만 전송한다고 TouchDesigner 영상이 웹 화면에 나타나지는 않는다. 첫 프로토타입은 브라우저 효과를 중심으로 검증하고, TouchDesigner 영상 표시 필요성이 확정되면 영상 경로를 추가한다.

## 시작 순서

1. 사용자와 브라우저 효과 + TouchDesigner 이벤트 전달 방식의 첫 프로토타입 방향을 결정한다.
2. 구현 승인 후 텍스트 입력, 시작 버튼, 수동 효과 테스트 버튼을 만든다. 카메라 없이 네 가지 효과를 먼저 검증한다.
3. 승인된 카메라 인식 도구로 손 추적을 연결하고 유지 시간, 신뢰도, 재발동 대기 시간을 조정한다. 펀치는 시간에 따른 전방 움직임으로 검증한다.
4. 양손 하트의 실제 모양 예시를 받아 판정 조건을 정하고, 사용 가능한 밈 파일을 연결한다.
5. TouchDesigner에 로컬 제스처 이벤트를 연결하고 브라우저와 동일한 이벤트가 수신되는지 확인한다. 이 단계의 설치와 실행 범위는 구현 전에 확인한다.
6. 기본 프로토타입이 작동하면 사용자에게 효과음 파일을 찾아 보내 달라고 요청한다. 이 시점에 부모 작업에도 알린다.
7. 허락된 오디오 파일을 연결하고, 필요할 때 TouchDesigner 영상 전송을 별도 구현한다.

## 오디오 준비

- 시작 버튼, BGM/SFX 개별 음량, 전체 음소거, 효과 이벤트별 SFX 연결 구조를 계획한다.
- 후보 BGM: Born Hater 인스트루멘털, https://www.youtube.com/watch?v=N-0j3JWORTc
- 게시자 Shekespearinator의 사용권을 확인하지 못했다. 제목의 OFFICIAL 표시는 이용허락 증거가 아니다. 다운로드나 음원 추출을 하지 않는다.
- 초기에는 오디오 파일 없이 구조를 준비하고, 이용이 허락된 파일을 나중에 연결한다.

## 첫 결정

첫 프로토타입을 브라우저가 효과를 렌더링하고 TouchDesigner에는 제스처 이벤트를 전달하는 방식으로 시작할지 결정하면 된다. TouchDesigner 영상이 웹에 반드시 표시되어야 한다면 먼저 영상 전송 설계를 확정한다.
